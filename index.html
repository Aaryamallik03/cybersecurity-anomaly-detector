01 / THE BIG IDEA

Not all weird is bad.
But weird is worth a look.

An anomaly detector looks for events that stand apart from what’s expected. It’s a helpful clue—not a verdict.

🧩
01 · COLLECT EVENTS

Bring every event in cleanly

Network events arrive through a REST API, follow one unified schema, and duplicates are ignored so counts stay honest.

✳
🔎
02 · SPOT THE ODD

Look for the outliers

Rules such as failed-login detection and a local scoring model flag unusual activity. Unusual doesn’t automatically mean malicious.

↗
🧠
03 · KEEP THE RECEIPTS

Explain every alert

Alerts come with an audit trail, and past events can be replayed to confirm the same input gives the same result.

◎
02 / TRY IT YOURSELF

Send an event.

This demo really runs in your browser. Events pass through duplicate protection, rules and a scoring step, then alerts and an audit trail appear. It uses its own simple logic to show the ideas, not the exact backend code.

HOW THIS DEMO DECIDES ✦

• The same event ID twice is ignored as a duplicate.
• 3 or more failed logins from one source within 60 seconds raise an alert.
• A successful login right after 3 or more failures raises an alert.
• Otherwise a simple 0–1 score decides: 0.7 or more raises an alert.

Same input, same result. That’s what replay checks.

Small project.
Serious curiosity.
